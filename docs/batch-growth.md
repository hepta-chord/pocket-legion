# 成長系の実装メモ

ゲームのルールは `plan.md` が正である。ここは型と関数の割り当てだけを書く。
実装が済んだらこのファイルは消す。

前提: 通路の描画修正が dev にマージされたあとに着手する。

## 1. レベルと経験値

`CharacterEntry` に足すもの:

```ts
level: number;          // 現在レベル。初期値 1
exp: number;            // 現在の経験値
maxLevel: number;       // レベル上限。主人公だけ Infinity ではなく大きな値 (999) を入れる
growth: number;         // 成長の補正値 (マスク)。上限到達時の伸び幅を決める
curve: 'linear' | 'early' | 'late';  // カーブの型 (マスク)
```

- `baseAttack` / `baseVitality` を持ち、`attack` / `vitality` は
  レベルから算出した実効値にする (`roster.ts` か `growth.ts` に計算を置く)
- **`growth` と `maxLevel` は個体ごとに振る。** 育ち切った到達値が全員同じだと
  最後に個性が消えるので、そこは揃えない。
  型は進捗 `t = (level - 1) / (maxLevel - 1)` の形だけを変える
  (直線 `t` / 早熟 `sqrt(t)` / 晩成 `t^2`)。
  どこまで伸びるかは `growth` と `maxLevel` が決める
- 経験値は戦闘に勝つと出撃メンバー全員に入る (ダウン中は入らない)。
  必要経験値はレベルに対して増える素直な式でよい

## 2. 酒場: 初期レベル・値段・引き直し

- **品揃えの初期レベルはランダムに振る** (浅い進行では低め、進むほど幅を広げる形でよい)
- `price` を定義から消し、`priceOf(entry)` で算出する。
  材料は**レベル上限・スキル・体力・攻撃力**
  - スキルごとの値付け表を持つ (`data/pricing.ts` を新設してよい)。
    コスト・威力・希少さから決め打ちでよい
  - 体力と攻撃力 (現在レベルでの実効値) を金額に換算して足す
  - レベル上限が高いほど高くする (伸びしろへの値付け)
  - レアリティの係数を掛けて、レアが従来の 400 G 帯、コモンが 120 G 帯に
    おおよそ収まるようにする
- **引き直し**: 金を払って品揃えを引き直す Action (`{ type: 'reroll-tavern' }`) を足す。
  賃料は所持金と釣り合う額の初期値を置く。出撃を終えると賃料は初期値に戻す
  (粘るほど高くなる形にするかは実装者の判断でよいが、素直な定額でも構わない)

## 3. 表示

- `FormationCharacterView` に `level` / `maxLevel` / `attack` を出し、
  キャラ枠・編成の一覧・酒場のカードのどれにも `Lv 1/20` の形で出す
- 成長の補正値とカーブは**表示しない** (マスク)

## 4. イベントの分岐

- ボス前以外のイベントにも二択を持たせる。`EventDef` に選択肢を
  0〜2 個持てる形にして、`resolve` / `resolve-alt` で解決する
  (ボス前の分岐が既にこの形なので、それを一般化する)
- **二択が出るのは 2 割程度**。毎回選ばせると選択そのものが作業になる
- 例: 宝で「金を取る / 回復薬を取る」、泉で「回復する / 経験値をもらう」など。
  中身は実装者が素直に決めてよい
- **選択肢はステージ側のウィンドウに出す** (操作列に混ぜない)

## 5. 敵

- 浅層ボスのダウン攻撃を 10 ターンに 1 回にする (`downEvery`)。
  中層・深層は今より少しだけ詰める程度でよい

## 6. sim

- 出撃前にレベルを振って計測できるようにする。
  区画ごとに「想定レベル」を置いて、そのレベルで測るのが素直
  (浅層 1、中層 10、深層 20 など)。数値の調整は計画側が行うので、
  実装は測れる形にするところまで

## 7. 数値

**実装では触らない。** 成長の伸び幅、値段の係数、想定レベルは初期値を置くだけにして、
`npm run balance` を見ながらの調整は計画側がまとめて行う。

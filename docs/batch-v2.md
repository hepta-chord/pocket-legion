## 1. 多段攻撃の仕組み (battle.ts / skills.ts)

- `SkillEffect` の attack に `hits?: number` を足す (省略 = 1)。
  power は **1 ヒットあたりの倍率** とする (0.5 × 2 回なら power 0.5, hits 2)
- useSkill の attack 処理をヒット数ぶんループする。
  **各ヒットが個別にダメージ計算され、コンボ倍率が乗り、コンボを 1 ずつ進める**
  (1 ヒット目は現在のコンボ、2 ヒット目は +1 されたコンボ、の順)。
  ログは 1 行にまとめてよい (例: 「連撃。120、135 与えた。」)
- 敵側も同様に `EnemyDef` へ足す:
  - `attackHits?: number` (省略 = 1)。通常攻撃 (applyNormalAction の attack) を
    ヒット数ぶんに刻む。**1 ヒットの威力 = attack / attackHits** (合計は従来と同水準)。
    乱数はヒットごとに振る
  - `bigHits?: number` (省略 = 1)。大技 (doBig) も同様に等分して刻む
  - `bigDispel?: number` (省略 = 0)。大技の最初に、味方の鼓舞・ガードのスタックを
    **ランダムに n 枚** 剥がしてからダメージヒットに入る (中層・深層ボス用)

## 2. バリアの再定義 (battle.ts)

plan.md「ダウン攻撃への対抗」に合わせる。
**バリアが無効化するのは 1 ヒットだけ。** 行動丸ごとではない。
多段はバリアを強くしすぎないための敵側の対抗なので、
バリア 1 枚で多段を受け切れる作りにしてはいけない。

- 敵の攻撃系の行動をヒットの列と見なし、**バリアは列の先頭ヒットだけ**無効化して消える。
  残りのヒットは通る (防御・ガードの軽減は通常どおり乗る)
- 防いだヒットに**伴う**特殊効果は一緒に無効になる:
  - downstrike は単発なので、ダメージもダウンも防がれる (現行どおり)
  - 大技の bigDispel は「ダメージ 0 の解除ヒット」として**列の先頭**に置く。
    バリアがあれば解除ヒットだけが防がれて消え、後続のダメージヒットは全部通る
    (骨の王: 解除を止めてガード無傷で一撃を受ける。
    八岐大蛇: 解除だけ止まり 8 発は刻まれる)
  - 多段の通常攻撃 (attackHits ≥ 2) は 1 ヒット目だけ防がれる
- スタン単体 (doStun) と行動枠の解除 (dispel) には **消費されない**。
  攻撃ではない行動でバリアを空撃ちさせないため (現状の doStun の扱いを維持する)
- 実装上は do 関数の先頭で一括 return する形をやめ、
  **ヒットのループの中で先頭ヒットのときだけ barrier を見て打ち消す**形にする
- 味方のバリアスキル (守りの膜、教団 slot2) は既にあるので仕組みだけ確認し、
  上記が成り立つように直す

## 3. 解除の 3 段階 (skills.ts / battle.ts / characters.ts / common-gen.ts)

`SkillEffect` の dispel を拡張する:

```ts
| { kind: 'dispel'; scope: 'one' | 'all'; power?: number }
```

- scope 'one' はランダムに 1 スタックだけ剥がす (鼓舞・ward の総スタックから 1 枚。
  枚数で重み付けした抽選でよい)。'all' は全部剥がす (現行動作)
- power があれば、剥がす前にその倍率の物理攻撃を 1 発入れる (コンボにも乗る)
- スキル 3 種:
  - **乱し**: physical 0 コスト、`{ kind: 'dispel', scope: 'one' }`
  - **崩し**: physical 1 コスト、`{ kind: 'dispel', scope: 'one', power: 0.8 }`
  - **浄化**: physical 2 コスト、`{ kind: 'dispel', scope: 'all' }`
- **カクサンの dispel (1 コスト全剥がし) を浄化 (2 コスト) に置き換える**。
  乱しは教団と王国の slot2 候補に、崩しは傭兵団の slot1 候補に足す
- **敵の行動枠の dispel も「ランダム 1 枚」に変える** (現状は全部消していて、
  解除中心の中層ボスに全剥がしをさせると鼓舞・ガードが一切維持できなくなるため)。
  ログは「◯◯の剥がし。ガードが 1 枚消えた。」のように何が消えたか言う

## 4. 味方スキルの多段バリエーション (common-gen.ts / characters.ts)

- コモン: **連撃** (physical 1 コスト、0.5 × 2 回) を新設し、
  王国と傭兵団の slot1 候補に足す
- レア (6 節の生成プール用):
  - **双撃**: physical 0 コスト、0.7 × 2 回 (レアの多段は高倍率)
  - **三連撃**: physical 0 コスト、0.5 × 3 回
- 必殺のバリエーション: **乱れ撃ち** (ultimate 3 コスト、**0.7 × 4 回**) を新設し
  レアの候補群に置く (合計 2.8。印籠の 3.0 を超えないよう抑える)

## 5. 泉脈の残存対策 (common-gen.ts / game.ts)

- 原因: 生成キャラはスキル定義ごとセーブに保存されるので、候補群から消しても
  セーブ内の個体に残っていた。**SAVE_VERSION 上げ (11 → 12) で破棄する** (冒頭の約束)
- 代わりのパッシブとして **商才** (戦闘勝利時の獲得金 +25%) を新設し、
  傭兵団の slot2 候補に足す。
  `PassiveDef.hooks` に `goldRate?: number` を足し、戦闘報酬の金の計算箇所で
  前衛の goldRate を合算して `× (1 + 合計)` を掛ける (端数は round)

## 6. レアの生成化 (common-gen.ts / game.ts / characters.ts)

plan.md「レアリティと入手」。固定レア 4 人 (r1〜r4) を廃止し、コモンと同じ生成にする。

- `generateRare(faction, rng, serial)` を common-gen.ts に足す:
  - 名前はコモンと同じ NAME_POOLS から引く (所持済み・品揃え内の重複回避も同じ規則)
  - slot1 候補 (0 コストはレアの特権): 斬撃 (0c、1.0 × 1)、双撃 (0c、0.7 × 2)、
    三連撃 (0c、0.5 × 3)
  - slot2 候補: 既存の greatBlade・魔力譲渡 (manaGift)・ward2・lastStand を
    characters.ts から移し、乱れ撃ち (4 節) と崩し (3 節) を加える。
    陣営ごとに分けず、レアは 1 つの候補群でよい (頭数が少ないため)
  - 数値の帯: baseAttack 120〜150 / baseVitality 45〜70 /
    growth 1.0〜1.5 / maxLevel 30〜40 / curve はランダム
- CHARACTERS から r1〜r4 を消す。`source` フィールドと
  unownedRares / hasUnownedRare の固定名簿前提の分岐も外す
- 酒場: TAVERN_RARE_CHANCE (0.15) はそのまま、当たったら固定レアではなく
  generateRare で生成する (陣営は雇用可能な陣営から抽選)
- ボス前の分岐イベント: 「レアを迎える」は **必ず generateRare** で出す。
  未所持レアの在庫という概念が消えるので、「レアが尽きて回復しか選べない」分岐も消える
- 「誰もいない」の条件を整理する: 全陣営が雇用上限か名前切れなら、
  コモンもレアも出せないので現行と同じ表示でよい
- ネームド (7 節) は生成と無関係。hero/mate/aide2 は固定のまま

## 7. ネームドのレアリティ (characters.ts / game.ts / view.ts)

- `rarity` を `'common' | 'rare' | 'named'` にし、hero / mate / aide2 を named にする
- ネームドの扱い (plan.md「初期の 2 人」): 酒場に出ない (もともと出ない)、
  **雇用上限に数えない** (陣営ごとの所持数カウントから除外する)、転生できない (8 節)
- ViewModel にレアリティを出している箇所 (game.ts 1147/1172 付近) は named をそのまま通し、
  表示名は「ネームド」にする

## 8. 転生所 (game.ts / main.ts / view.ts)

plan.md「転生所」。拠点のドリルダウンに施設を 1 つ足す。

- ホーム一覧を「酒場」「道具屋」「転生所」「探索」にする
- 転生所では所持キャラ一覧 (ネームド除く) を出し、選ぶと詳細と費用を見せて確認の上で転生する
- Action `{ kind: 'rebirth'; charId: string }` を足す。処理:
  - 費用 = `Math.floor(priceOf(entry) / 2)`。所持金が足りなければ押せない
  - **名前・陣営・id は保ち**、レベル 1 / exp 0 に戻して、
    基礎値・growth・maxLevel・curve・スキルを同じレアリティの生成プール
    (コモンは generateCommon、レアは generateRare の帯) で引き直す。
    generateCommon / generateRare を「名前を固定して中身だけ振る」形に
    切り出すと共通化できる
  - 出撃中は使えない (拠点の施設なので自然にそうなるはず)
- 編成に入っているキャラを転生してもスロットはそのまま (実効値が変わるだけ)

## 10. ボスの個性 (enemies.ts)

plan.md「敵の行動と予告」のボス個性に合わせて BOSSES と bossSlots を作り替える。
sectorId ごとの一律 slots をやめ、ボスごとに slots と多段・解除の設定を持たせる。

- **浅層・穴蜘蛛の女王** (自己強化型): 現行のまま。
  枠 1 `攻撃 9 : 無 1`、枠 2 `鼓舞 5 : 防御 5 : 攻撃 1 : 無 2`
- **中層・骨の王** (解除型):
  - 枠 1 `攻撃 9 : 無 1`、枠 2 `解除 5 : 鼓舞 2 : 防御 2 : 攻撃 2 : 無 2`
  - 大技 (亡者の号令): `bigDispel: 1`、`bigMul: 5.0`、単発 (bigHits 1)。
    「1 発目で剥がし、2 発目で本命」をログでもその順に見せる
- **深層・八岐大蛇** (スタン・多段型): **名前を「深淵の使者」から「八岐大蛇」に改める**
  - `attackHits: 2` (通常攻撃はデフォルトで 2 回刻み)
  - stunEvery 3 (現行 4 から詰める)、stunRange 2〜4
  - 枠 1 `攻撃 9 : 無 1`、枠 2 `攻撃 5 : 鼓舞 2 : 防御 2 : 無 2`
  - 大技: 名前を「八首の顎 (やつがしらのあぎと)」にし、
    `bigHits: 8`、`bigMul: 6.0` (1 ヒット 0.75 相当)、`bigDispel: 1`。
    バリアで防げるのは先頭の解除ヒットだけで、8 発の刻みはガードと防御で受けさせる
- 雑魚: 中層以深 (depth 11 以上) の雑魚は 30% で `attackHits: 2` を持つ
  (合計威力は同じ。絵替わりであって難度は変えない)

## 11. 必殺の属性と魔法のコスト帯 (skills.ts / characters.ts / common-gen.ts)

plan.md「スキル配分の指針」の追記に合わせる。

- **elementOf を変える**: 属性が魔法になるのは category 'magic' だけ。
  ultimate は physical に落とす (`def.element ?? (category === 'magic' ? 'magic' : 'physical')`)。
  必殺が魔法耐性で半減しなくなる。element での個別上書きは残す
- **コーモンの必殺を「必殺・印籠」(shortName「印籠」) に改名し、power 3.0 に上げる**
  (現行は必殺・断 2.8)。id は hero-finish のままでよい
- 魔法の単体攻撃にコスト帯を足す (いずれも category 'magic'):
  - **閃光**: 2 コスト、power 3.0。教団の slot1 候補に足す
  - **極光**: 3 コスト、power 4.0。レアの slot2 候補 (6 節) に足す
  - 既存の光弾 (1 コスト 2.0) はそのまま
- 乱れ撃ちは 0.7 × 4 回にする (4 節の修正)

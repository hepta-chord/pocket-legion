# Pocket Legion

文字だけのカジュアル編成型ダンジョンクローラー。
迷宮都市の拠点で部隊を編成・強化し、マップレスの 3D ビューダンジョンをひたすら進み、
ボスを倒して帰還するループを繰り返す。シナリオは持たず、編成強化とシンプルな戦闘の
面白さに絞ってある。

スマートフォンのブラウザで遊ぶ前提で、GitHub Pages に置いて URL で配る。
PWA (Service Worker) に対応していて、一度開けばオフラインでも起動できる。

企画と仕様は [docs/plan.md](docs/plan.md) にある。ここでは遊び方と実装の要点だけをまとめる。

## 遊び方

1. **拠点**: 酒場 (キャラの雇用)・道具屋 (回復薬の購入)・編成 (前衛 6 人を選ぶ) で
   出撃前の準備をする。控えに上限は無く、所持キャラ全員が出撃メンバー (デッキ) になる
2. **出撃**: 解放済みの区画 (浅層 → 中層 → 深層) を選んで潜る。区画ごとに開始深度と
   ボスの深度が決まっている
3. **探索**: マップは持たない。「進む」を押すたびに深度が 1 つ増え、イベントが 1 つ抽選される。
   ボスの 1 つ手前の深度には固定でボス前の分岐イベント (回復 / レア加入) が置かれ、
   ボスの深度に着くと自動でボス戦になる
4. **戦闘**: 敵は常に 1 体 (群れは頭数を HP と攻撃力に畳み込んで表現)。
   前衛 6 人でマナとスキルを使って戦う (仕組みは次節)
5. **帰還**: ボスを倒すと次の区画が解放され、その出撃で得た金とアイテムを持ち帰る。
   全滅すると拠点に戻され、その出撃ぶんの金とアイテムだけを失う
   (所持キャラ・レベル・陣営倍率は失わない)

### 探索イベント

進むたびに抽選される内容は、戦闘系 (通常の敵 / 強敵) のほか、宝箱・泉・隊商・祠・
落石・死体・休息・生存者 (加入)・何も無い、と多岐にわたる。
祠・落石・休息は「選ばせるためのイベント」なので、出た時点で必ず二択になる
(祈る/壊す、押し通る/迂回する、休む/先を急ぐ)。宝箱・泉は稀に (2 割程度) しか
二択にならず、大半は単一の行動で解決する。
罠は単独のイベントとしては出てこず、宝箱・「何も無い」・死体を解決したときに、
まれに (割合はイベントごとに違う) 隠れた結果として出る。

## 戦闘の仕組み

- **マナ**: 毎ターン払い出される (奇数ターン 2、偶数ターン 3 が基礎。中層クリアで 3/3 に成長)。
  使い残しは上限 10 まで持ち越せる
- **コスト上昇**: 物理スキルはそのターン中だけコストが +1 されて頭打ち (ターン終了でリセット)。
  魔法・必殺スキルは出撃を通してコストが上がり続け、上限は無い (帰還でリセット)。
  物理は消耗しない手数、魔法・必殺は切りどころを選ぶ札、という役割分担になっている
- **防御**: 1 マナで 1 枚積める常設コマンド (最大 4 枚)。重ねるほど軽減率が上がり
  (20% / 45% / 70% / 90%)、パーティ全体に効いてターン終了で消える
- **鼓舞・ガード**: スキルで積む持続バフ (どちらも 3 枚まで、3 ターン持続)。
  鼓舞は攻撃 +20%/枚、ガードは被ダメージ −20%/枚。剥がしスキルで敵の鼓舞・防御を
  剥がすこともできる (味方も剥がされうる)
- **コンボ**: 同一ターン内で攻撃を重ねるたびダメージ倍率が +15% (ターン終了でリセット)。
  安い物理でコンボを稼いでから魔法・必殺で〆るのが基本の火力の出し方になる
- **バリア・身代わり**: 予告される大技・ダウン攻撃への対抗手段。バリアは補助スキルで
  張る一回限りの完全無効化、身代わりは壁役のパッシブでダウンを肩代わりする
- **ダウン攻撃・スタン**: 特殊行動 (大技・ダウン攻撃・スタン) はそれぞれ専用のクールタイムで
  行動枠の抽選とは別に撃たれる。予告が出るのは大技とダウン攻撃だけ。
  ダウンしたキャラはその出撃のあいだ戦闘から離脱し (帰還で全員回復)、
  空いた前衛には控えの同陣営がランダムで自動補充される。スタンは対象をそのターンと
  次のターン行動不可にする (戦闘をまたいで持ち越さない)
- **逃げる・交代**: 「逃げる」は宣言から 1〜3 ターン後 (乱数) に発動するトグルで、
  発動までは敵の攻撃を凌ぎながら退く。手動交代はマナを使わず、ダウン扱い + クールタイム
  3 ターンだけを代償に何人でも入れ替えられる

パーティ HP は個別ではなく共有制で、敵の通常攻撃はこれを削り、大技は HP に加えて
対象 1 人をダウンさせる。

## 成長

- **レベルと上限**: 経験値は戦闘に勝つと出撃メンバー全員 (ダウン中を除く) に入り、
  個人の攻撃力と体力を伸ばす。レベル上限はキャラごとに違い (コモンは 20 前後、
  レアはそれより高い)、主人公だけは上限が無い
- **成長カーブ**: 伸び方 (直線型 / 早熟型 / 大器晩成型) と上昇率・上限はキャラごとの
  マスクパラメータで、プレイヤーには数値を見せない
- **陣営倍率**: 実効ステータス = 基礎値 (レベル込み) × 陣営倍率。陣営倍率は
  「所持している同陣営キャラの実効値合算 ÷ 定数」で決まり (上限 2.0 倍)、
  同陣営を集めて育てるほど全員が底上げされる。前衛に同陣営を並べると別途、
  同陣営補正 (人数に応じた一時的なステータス増) も乗る
- **陣営の人口**: 王国 > 教団 > 傭兵団 > 辺境の順に人口が少ない。人口比は酒場に
  並ぶ確率と陣営ごとの雇用上限に反映され、人口の少ない陣営ほど一人ひとりが強い、
  という非対称でつり合わせてある

## 開発

```
npm install
npm run dev      # 開発サーバー
npm test         # テスト
npm run build    # 型検査 + 本番ビルド
npm run balance  # 戦闘バランスの計測 (ヘッドレス自動プレイ)
npm run icons    # PWA アイコン (public/icon-192.png, icon-512.png) の再生成
```

## 構成

```
src/
  main.ts            起動。Renderer の選択、入力と画面の接続、Service Worker の登録
  game.ts             最上位の状態機械 (拠点 / ダンジョン / 戦闘 / 結果)。ViewModel を返す
  view.ts             描画層に渡すデータの型。見た目を含まない
  battle.ts           戦闘の状態遷移 (マナ、コスト上昇、防御、鼓舞・ガード、コンボ、
                      交代、ダウン、ダウン攻撃、スタン、耐性、逃げる)
  run.ts              出撃 1 回ぶんの進行 (深度、イベント抽選、パーティ、ダウンの回収)
  formation.ts        編成 (前衛 6 枠) の型と操作
  roster.ts           所持ベースの陣営倍率の計算
  growth.ts           レベルと成長カーブ (マスクパラメータ) の計算
  rng.ts              シード付き乱数 (mulberry32)
  save.ts             localStorage への保存と復元
  data/
    characters.ts    固定の主人公・相棒・レアの定義と、生成コモンが共有する型
    common-gen.ts    コモンのその場生成 (陣営ごとの名前・スキル候補群から抽選)
    skills.ts        スキルの型 (系統とコスト上昇の規則)
    enemies.ts       敵とボスの生成
    factions.ts      陣営の定義
    sectors.ts       区画 (開始深度・ボスの深度) の定義
    dungeons.ts      迷宮の定義 (区画をまとめる、複数迷宮に備えた形)
    events.ts        探索イベントの定義・重み・二択の抽選
    pricing.ts       酒場の値付け (レベル上限・スキル・体力・攻撃力から計算)
  render/
    renderer.ts      Renderer インターフェース
    text-renderer.ts 疑似 3D 通路と戦闘画面の文字描画
    corridor.ts      疑似 3D 通路のアスキー生成
    portraits.ts     敵の画像枠に出すアスキーアートのプレースホルダ
    event-icons.ts   探索イベント種別ごとの小さなアイコン
  sim/
    autoplay.ts      ヘッドレスの自動プレイ (編成別の勝率・平均被害・到達深度)
    report.ts        計測結果を表に畳む
scripts/
  balance.ts         バランス計測の入口 (npm run balance)
  make-icons.mjs     PWA アイコンの生成 (npm run icons)
public/
  manifest.webmanifest  PWA マニフェスト
  sw.js                 Service Worker (オフラインキャッシュ)
  icon-192.png / icon-512.png
```

テストは `src/**/*.test.ts` に置く。

`game.ts` と `view.ts` は `render/` を import しない。
見た目をタイル画像に替えたいときは、`Renderer` を実装した `TileRenderer` を `src/render/` に足し、
`src/main.ts` の 1 行を差し替えるだけで済む形にしてある。

## PWA

`public/manifest.webmanifest` と `public/sw.js` はビルド成果物 (`dist/`) にそのままコピーされ、
`index.html` から参照される。`main.ts` が本番ビルドでだけ Service Worker を登録する。
`sw.js` は入口 (`index.html` など) をネットワーク優先、ハッシュ付きの `assets/` を
キャッシュ優先で扱う。入口までキャッシュ優先にすると新しいビルドを出しても
古い版が返り続けてしまうため、更新は必ず入口から届く形にしてある。

## 公開

`main` に push すると `.github/workflows/pages.yml` がビルドして GitHub Pages に配信する。
リポジトリの Settings → Pages で Source を「GitHub Actions」にしておく。
